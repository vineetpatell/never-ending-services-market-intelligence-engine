Functional and non-functional requirements
1. Purpose
This SRS translates the product goals into testable system behaviours for a local-first personal application. Requirements
are implementation-neutral unless a technology is explicitly specified.

3. Non-functional requirements
  NFR-001 Usability: beginner tasks use plain-language labels and guided steps.
  NFR-002 Accessibility: keyboard support, visible focus and reduced-motion preference.
  NFR-003 Privacy: no real sensitive documents in demo data; local-first intent documented.
  NFR-004 Security: no frontend secrets; validate data at boundaries when backend is introduced.
  NFR-005 Reliability: handle missing, stale and unavailable data distinctly.
  NFR-006 Performance: core UI loads without waiting for 3D; benchmark on target hardware.
  NFR-007 Maintainability: reusable components, typed contracts and domain logic separation.
 
4. Constraints and exclusions
  No live order routing or insurance purchases in the initial release.
  No live market feed until an authorised provider is selected and integrated.
  No claim that a demo AI response is a real model output.
  No cloud database or external AI integration in the prototype unless explicitly approved.
 
5. Acceptance test examples
  AT-01: User can navigate from Home to each major module and back without dead links.
  AT-02: Switching theme does not break text contrast or chart labels.
  AT-03: Paper trading page always shows the simulation-only banner.
  AT-04: Policy extraction UI requires review before marking data verified.
  AT-05: All animation demos replay and obey reduced-motion settings.
  AT-06: Disabling WebGL does not disable any functional workflow.
